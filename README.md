# Trainster

Первый Android-прототип для поездок с друзьями. Организатор собирает путешествие из блоков «Передвижение», «Прогулка», «Пауза / ночёвка», публикует план и приглашает участников по коду. Участник получает опубликованный план, который сохраняется на телефоне.

## Стек

- Kotlin, Jetpack Compose, Material 3; Android 8.0+ (API 26).
- FastAPI, SQLite, Python 3.12+.
- Яндекс Расписания: реальные станции и автобусные остановки, датированные рейсы электричек, поездов и автобусов.
- MapLibre Native 11.11.0 + OpenFreeMap: векторная карта без ключа, GPS и скачиваемые области.
- Valhalla / OpenStreetMap: реальные пешеходные пути через FastAPI без ключа.
- Photon / OpenStreetMap: поиск адресов и названий мест без ключа.
- OpenStreetMap / Overpass: построение предполагаемого железнодорожного пути по реальной сети путей. Это не подтверждённая нитка движения конкретного рейса РЖД.

В приложении и сервере нет встроенного демонстрационного путешествия и вымышленных расписаний. Без ключа Расписаний поиск сообщает о необходимости настройки. Карты и пешеходные маршруты работают без ключей.

## 1. Ключи сервисов

Нужен только ключ **API Яндекс Расписаний** из [кабинета разработчика Яндекса](https://developer.tech.yandex.ru/). Сохраните его на сервере в `server/.env`: `YANDEX_RASP_API_KEY=...`. Уже настроенный ключ менять не нужно.

MapLibre использует стиль `https://tiles.openfreemap.org/styles/liberty`, ключ и оплата не нужны. `MAPKIT_API_KEY` больше не используется. При необходимости собственный стиль можно задать через `MAP_STYLE_URL` в `local.properties` и пересобрать APK.

Пешеходные маршруты сервер запрашивает у публичного Valhalla. Это сервис без гарантии доступности для небольших нагрузок; собственный экземпляр подключается через `TRAINSTER_WALK_ROUTING_URL` в `server/.env`.

Копирование сайта РЖД не используется как рабочая интеграция: публичный стабильный интерфейс с геометрией конкретного поезда не подтверждён. Подробности и первичные ссылки: [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md).

## 2. Сервер на компьютере

Из корня проекта в PowerShell:

```powershell
.\scripts\run-server.ps1 -Install
```

Скрипт создаёт виртуальное окружение `server/.venv`, устанавливает зависимости, создаёт `.env` из примера и запускает сервер на `0.0.0.0:8000`. Если `python` не установлен или Windows предлагает Microsoft Store, укажите путь к Python 3.12+:

```powershell
.\scripts\run-server.ps1 -Python 'C:\path\to\python.exe' -Install
```

После заполнения `.env` перезапустите сервер. Документация API: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs), проверка: [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health). SQLite и кеш источников создаются локально; не добавляйте их в Git.

## 3. Android Studio

1. Открыть **корневую папку Trainster**, содержащую `settings.gradle.kts`.
2. Скопировать `local.properties.example` в `local.properties`, указать `sdk.dir`. Ключ карты не нужен.
3. Использовать JDK 17 или 21 для Gradle. Установленная здесь Android Studio содержит JBR 25, который не подходит для Gradle 8.14.5. Для этой рабочей среды JDK 21 находится в `C:\Users\fotob\.jdks\jbr-21.0.11`, локальная настройка `GRADLE_LOCAL_JAVA_HOME` уже подготовлена. При необходимости выберите её в Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK.
4. Нужны Android SDK Platform 36 и Build Tools 36.0.0. Дождаться Gradle Sync и запустить модуль `app` на телефоне или эмуляторе.

Сборка через PowerShell:

```powershell
.\scripts\build-android.ps1 -JavaHome 'C:\Users\fotob\.jdks\jbr-21.0.11'
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Debug-сборка разрешает локальный HTTP для разработки. В release доступен HTTPS; перед размещением на сервере настройте TLS.

## 4. Подключить телефон / эмулятор

- Эмулятор Android Studio: адрес сервера в приложении `http://10.0.2.2:8000`.
- Телефон в той же Wi-Fi сети: `http://<IPv4 компьютера>:8000`; адрес компьютера можно посмотреть через `ipconfig`. Если Windows Firewall блокирует подключение, разрешите Python входящие подключения **для частной сети**.
- Телефон через USB с включённой отладкой: `adb reverse tcp:8000 tcp:8000`, затем адрес `http://127.0.0.1:8000`.
- Адрес сервера меняется на экране входа / в настройках приложения. Переключение сервера требует нового входа, чтобы не смешивать аккаунты разных серверов.

## 5. Проверка первой поездки

1. Зарегистрировать организатора, создать пустую поездку.
2. Добавить «Передвижение»: электричка / поезд / автобус → станции или остановки → дата → реальный рейс → остановки. При необходимости отдельно запросить путь по железной дороге.
3. Добавить прогулку: «По адресу» → ввести город, улицу/дом или название → «Найти» → выбрать результат и проверить на карте → «Выбрать это место». Либо «На карте» → нажать на нужную точку → подтвердить. Затем задать название и время посещения. Координаты и долгое нажатие на встроенной карте также доступны. Построить пешеходный путь; добавить ночёвку.
4. Сохранить и опубликовать. На втором устройстве создать другой аккаунт и присоединиться по коду.
5. Отредактировать черновик: участник продолжает видеть опубликованную версию. После публикации новая версия появляется при синхронизации.
6. Открыть «Участники» у организатора: выбрать друга, включить или исключить этапы, добавить общую и поэтапные личные заметки. Настройки применяются сразу, отдельно от черновика общего плана. Участник скачивает только свои настройки; заметки других ему не передаются.
7. Разрешить уведомления Android. Запустить поездку и выбрать текущий этап: участник увидит изменения и уведомление при ближайшей проверке. Публикации и личные изменения тоже вызывают уведомления; сохранение черновика — нет.
8. На карте приблизить нужный город → «Скачать область» → дождаться «Готово» в «Загрузках». Повторить для других городов.
9. Нажать на метку станции или места → «Открыть в картах». Android откроет установленное приложение карт или предложит выбор; передаются координаты точки.
10. Отключить интернет: ранее полученный план, остановки, заметки и линии доступны локально. Восстановить связь и обновить план.

## Время и расписание

Даты и часы отображаются в часовом поясе телефона, с подписью UTC-смещения. При изменении системного пояса открытые экраны обновляются без перезапуска. Приложение не привязывается к московскому времени; настройки телефона открываются из «Подключение» → «Настройки времени телефона». Для установленного здесь эмулятора исправлен исходный GMT на Europe/Moscow.

Нажмите на транспортный этап: карточка показывает отдельные отправление/прибытие, станции, полные даты и переход «+1 день» при ночной поездке. Время в пути считается между абсолютными моментами отправления и прибытия, независимо от смещения часов. Остановки имеют отдельные колонки прибытия/отправления; при переходе даты она указана рядом с временем. Та же карточка доступна для поездов, электричек и автобусов.

## Границы прототипа

- Конфигурация путешествия остаётся лёгкой; карты хранятся отдельно в SQLite MapLibre на каждом телефоне. Участники скачивают области самостоятельно. Экран «Загрузки» показывает готовность, объём, паузу, продолжение, открытие и удаление области.
- Скачивается видимый прямоугольник до уровня 14 (векторные тайлы можно увеличивать дальше). Большие области отклоняются; загрузка ограничена 2700 ресурсами и 45 МБ, не более 4 запросов одновременно. Это запас под [лимиты OpenFreeMap](https://openfreemap.org/tos/) 3000 тайлов / 50 МБ. При достижении лимита незавершённая область не объявляется готовой: удалите её и выберите меньший участок. Нельзя гарантировать заранее конкретный размер файла.
- Загрузка идёт при открытом приложении; незавершённые области после перезапуска стоят на паузе. Только «Готово» означает завершённый офлайн-пакет. Вне сохранённого прямоугольника и на других детализациях карта может потребовать сеть.
- Адресный поиск требует интернета и связи с сервером, выполняется кнопкой «Найти». Найденные точки и адреса сохраняются в плане для офлайна. На скачанной карте можно выбрать точку без интернета. При добавлении/перемещении места пешеходный путь нужно построить заново.
- Новый путь Valhalla/OSM сохраняется с планом без прежнего 30-дневного срока MapKit. Старые пути MapKit по-прежнему очищаются через 30 дней; для них нажмите «Построить маршрут по точкам» в конструкторе. Построение новых путей требует сети и связи с сервером; офлайн доступны сохранённая линия и GPS. Офлайн-голосовой навигации нет.
- Публичный Valhalla используется с лимитом 1 запрос/секунду на процесс сервера, кешем 7 дней / 128 путей и максимум 25 точками / 50 км между точками на прогулку. Это прототип для небольшой компании. Для нескольких серверных процессов/публичного приложения используйте собственную маршрутизацию или общий ограничитель.
- Расписания не являются подтверждёнными данными о задержках. Время получения и ссылка на источник сохраняются с рейсом. Во время поездки организатор может выбрать текущий этап вручную.
- GPS показывает положение телефона, а не независимую позицию поезда. Без актуальной геопозиции не выдаётся вымышленная точка поезда.
- OSM-трассировка может не найти связный путь, отличаться на развилках или быть недоступна из-за ограничений Overpass. В этом случае остаются остановки и честное сообщение без выдуманной линии.
- Полный план синхронизируется при открытом приложении. Изменения для уведомлений проверяются каждые 10 секунд при открытом приложении и через WorkManager в фоне с периодом 15 минут; Android может отложить фоновую проверку. Это опрос своего сервера, мгновенная push-доставка не подключена. Без доступа к серверу события ждут восстановления связи. При первом входе задаётся начальная отметка без уведомлений о старых событиях. Отключение доступно в настройках.
- Справочник автобусов обновится автоматически после обновления сервера. Доступны только рейсы и остановки, которые публикует Яндекс Расписания, с точным временем отправления. Это не полный справочник всех городских автобусов. Дорожная геометрия автобуса не строится.
- Личные планы настраиваются по опубликованным этапам и сохраняются у участника офлайн. Организатору для их редактирования нужна связь с сервером. Если участник пропускает текущий общий этап, экран «Сейчас» объясняет это.
- Отслеживание всех участников, продажа билетов и офлайн-очередь отправки изменений не реализованы.
- Один организатор, участники читают опубликованный план. Токен входа ограничен по сроку; пароль не сохраняется на телефоне.

Контракт данных и API: [docs/API.md](docs/API.md). Проверки и фактическое состояние сборки: [docs/VALIDATION.md](docs/VALIDATION.md).

Размещение на VPS Debian13 без домена с HTTPS поIP: [инструкция](docs/DEPLOYMENT.md).
