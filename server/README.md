# Trainster server

Python 3.12+, FastAPI, SQLite. Здесь нет тестовых поездок, фиктивных расписаний или учётных записей по умолчанию.

## Запуск в PowerShell

```powershell
cd server
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Впишите YANDEX_RASP_API_KEY в .env, затем:
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Если `python` не установлен отдельно, в этой рабочей среде доступен
`C:\Users\fotob\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`.

Документация API: <http://localhost:8000/docs>. Проверка: <http://localhost:8000/health>.
Эмулятор Android обращается к `http://10.0.2.2:8000/`, телефон в той же сети — к
`http://<IPv4 компьютера>:8000/`. Если Windows спросит доступ к частной сети,
разрешите его для этого сервера. На публичном сервере подключите HTTPS.

Скопированный `.env` читается из `server/` независимо от текущей папки запуска.
Переменные среды имеют приоритет. `TRAINSTER_ENV_FILE` позволяет выбрать иной файл,
`TRAINSTER_DATABASE` — SQLite-файл (относительный путь считается от `server/`).
Ключ хранится только на сервере; значение не возвращается приложению и не включается в URL.

## Реальные расписания

Ключ выдаётся в [кабинете разработчика Яндекса](https://developer.tech.yandex.ru/).
Подключите API Яндекс Расписаний, сохраните ключ в `YANDEX_RASP_API_KEY` и
перезапустите сервер. Без ключа аккаунты и путешествия работают, а поиск станций
и рейсов возвращает HTTP 503 с объяснением. Проверка конфигурации — `/api/v1/config`.

Адаптер использует `https://api.rasp.yandex-net.ru/v3.0/`, передаёт ключ в заголовке
`Authorization` и запрашивает только прямые датированные рейсы. Справочник реальных
железнодорожных станций и автобусных остановок загружается в SQLite при первом поиске (большой файл), затем
обновляется раз в 7 дней. При недоступности поставщика существующий справочник сохраняется;
свежий поиск расписания всё равно обращается к API. Поиск станций ищет введённые слова с учётом распространённых окончаний; выбирайте станцию из результатов, а не вводите произвольный код.

Тип транспорта выбирается параметром `mode=suburban|train|bus` у `/api/v1/stations`
и `/api/v1/services`. Для автобуса поиск показывает остановки и автостанции с
контекстом города/региона; для поездов — железнодорожные станции. Расписания
автобусов и остановки получаются из тех же методов Яндекс Расписаний. Наличие
конкретного рейса зависит от покрытия поставщика. Дорожная геометрия автобуса не
загружается; железнодорожный трассировщик для него не вызывается.

Маршрут рейса содержит именно участок между выбранными станциями. Ответы API не
считаются информацией о фактических задержках. `service_date` сохраняет `start_date`
из поиска: дата начала рейса может отличаться от даты посадки после полуночи.

Источники: [поиск рейсов](https://yandex.ru/dev/rasp/doc/ru/reference/schedule-point-point),
[остановки](https://yandex.ru/dev/rasp/doc/ru/reference/list-stations-route),
[справочник](https://yandex.ru/dev/rasp/doc/ru/reference/stations-list),
[условия](https://yandex.ru/legal/rasp_api/ru/).
Данные предоставлены сервисом [Яндекс.Расписания](https://rasp.yandex.ru/).

## Линия железной дороги

`GET /api/v1/services/geometry` вызывается отдельно от расписания. Он пытается
сопоставить станции с реальной железнодорожной сетью OpenStreetMap через Overpass.
Это вычисленный путь по рельсам, а не подтверждённая перевозчиком трасса данного
рейса. Если сеть неполная, станции не сопоставились или запрос слишком большой,
возвращается пустая геометрия с объяснением. Прямые линии между станциями не выдаются
за железнодорожный путь. Данные: [© OpenStreetMap contributors](https://www.openstreetmap.org/copyright).

Дополнительные настройки: `TRAINSTER_OVERPASS_URL`, `TRAINSTER_RAIL_CACHE_DIR`,
`TRAINSTER_RAIL_CACHE_HOURS` (по умолчанию 168). API Overpass может временно
ограничить запросы; сохранённый план остаётся доступен.

## Поиск адресов и мест

`POST /api/v1/places/search` с авторизацией и JSON `{ "query": "Ростов Великий Соборная площадь", "near": null }` возвращает до 6 настоящих мест. Используется [Photon](https://github.com/komoot/photon) / OpenStreetMap без ключа. Свой совместимый endpoint задаётся через `TRAINSTER_PLACE_SEARCH_URL`. Публичный демосервис предназначен для небольшой нагрузки и не гарантирует доступность.

Поиск запускается пользователем кнопкой «Найти», без фонового автодополнения. На процесс сервера — не более одного сетевого запроса в секунду; SQLite-кеш до 256 поисков на 7 дней. Запрос в POST-теле не попадает в обычный access log; ключ кеша хешируется. В Photon уходят строка поиска и, если есть, округлённая точка предыдущего места для приоритета близких результатов, а не GPS участника или токен входа. Для русского адреса используется локальное имя: публичный Photon не поддерживает `lang=ru`, выбран `lang=default`.

Найденный адрес сохраняется в `WalkPoint.address`, отображается в конструкторе и сохраняется при синхронизации/офлайн-чтении. Выбор точки на карте работает на клиенте без запроса геокодирования; на скачанной карте связь с сервером не требуется.

## План и синхронизация

Организатор видит черновик, участники — опубликованный снимок названия, описания и
блоков. Сохранение проверяет `expected_revision`, при конфликте возвращает 409.
Публикация изменённого плана повышает `version`; повторная публикация того же снимка ничего не меняет. Нельзя присоединиться к неопубликованной поездке.
Запуск и текущий этап доступны только организатору; текущий этап выбирается из
опубликованного плана. Пароли хешируются PBKDF2-SHA256 с отдельной солью (600000
итераций). Сессии истекают через 30 дней; SQLite хранит SHA256 токенов, а не токены.

Пешеходные пути теперь строит Valhalla / OpenStreetMap без ключа: `POST /api/v1/walking/route`, 2–25 точек, не более 50 км между точками. По умолчанию публичный `https://valhalla1.openstreetmap.de/route`, для своего сервера задайте `TRAINSTER_WALK_ROUTING_URL`. Лимит 1 запрос/секунду на процесс, SQLite-кеш 7 дней / 128 путей. Сервис получает только координаты, кеш не содержит названий пользовательских мест. При ошибке путь не подменяется прямой линией.

Новые пути `routing_source=valhalla_osm` сохраняются в плане для офлайн-использования без срока MapKit. Только старые пути `yandex_mapkit` (или без источника) очищаются через 30 дней; точки и заметки сохраняются. Карты скачиваются на Android через MapLibre / OpenFreeMap отдельно от сервера и лёгкой конфигурации поездки.

## Индивидуальные планы участников

Организатор получает участников через `GET /api/v1/trips/{id}/participants` и
задаёт для каждого исключённые этапы, общую личную заметку и заметки к отдельным
этапам через `PUT /api/v1/trips/{id}/participants/{user_id}`. Ссылки допускаются
только на опубликованные этапы, сохранение проверяет `expected_revision` именно
индивидуального плана (409 при конфликте). Такие изменения действуют сразу.

В `Trip.personalization` участник получает только собственные настройки для
офлайн-кеша; общий опубликованный маршрут и текущий этап сохраняются. Другие
участники не видят его заметки. При удалении этапов из новой публикации сервер
удаляет устаревшие ссылки и повышает затронутые индивидуальные ревизии.

## События для уведомлений

`GET /api/v1/events` с авторизацией возвращает пустой список и текущий курсор
для первого подключения. Затем клиент вызывает `/api/v1/events?after=<cursor>`
и сохраняет курсор отдельно для аккаунта и сервера. Страницы до 100 событий,
`has_more=true` требует следующего запроса; пустая страница тоже продвигает курсор.
При замене базы курсор за пределами текущего максимума сбрасывается (`reset=true`).

Публикация, запуск/смена этапа/завершение, первое присоединение и индивидуальные
изменения пишутся в SQLite в одной транзакции с изменением данных. Черновики и
повторные запросы без изменения не создают оповещения. Участник получает события
только после своего присоединения. Личные изменения адресованы конкретному
участнику и организатору; содержание личных заметок не попадает в текст события.

Это очередь для опроса, без настройки FCM: сервер не может сам гарантировать
мгновенную доставку на Android в фоне. Клиент определяет частоту проверки и
учитывает ограничения фоновых задач Android. Полный контракт — [docs/API.md](../docs/API.md).

Миграции SQLite добавляют таблицы и столбцы при старте, сохраняя существующие
аккаунты, членство, черновики и кеши.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q --basetemp=.pytest-tmp
```

Тесты используют отдельные временные SQLite-файлы и HTTP fixtures только внутри
`tests/`; рабочий сервер всегда обращается к настоящему поставщику. Проверяются
пароли, сессии, права, опубликованные версии, параллельное сохранение, ночные рейсы,
обрезка остановок, автобусы, приватность индивидуальных планов, события, миграция базы, ошибки поставщика и удаление просроченного картографического кэша.
