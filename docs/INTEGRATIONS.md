# Реальные источники данных

## Яндекс Расписания

Базовый адрес: `https://api.rasp.yandex-net.ru/v3.0/`. Ключ передаётся в заголовке Authorization сервером. Мобильное приложение получает только нормализованные данные, не ключ.

- [Поиск рейсов между станциями](https://yandex.ru/dev/rasp/doc/ru/reference/schedule-point-point): `search`, станции, дата, тип `suburban` / `train` / `bus`.
- [Нитка маршрута](https://yandex.ru/dev/rasp/doc/ru/reference/list-stations-route): `thread`, UID рейса, дата и нужный участок; остановки, прибытия, отправления.
- [Список станций](https://yandex.ru/dev/rasp/doc/ru/reference/stations-list): `stations_list`, коды и координаты. Сервер хранит справочник для поиска и обновляет его.
- [Условия API](https://yandex.ru/legal/rasp_api/ru/): атрибуция, использование данных и требования к мобильным приложениям. Доступность сервиса не означает доступность любых способов хранения/распространения; перед публичным запуском сверить выбранный сценарий с актуальными условиями.

В документированной схеме нитки нет подробной геометрии рельсов. Приложение не объявляет данные расписаний фактическим отслеживанием движения и не рисует позицию поезда по часам как точный GPS.

## MapLibre / OpenFreeMap

[MapLibre Native Android](https://github.com/maplibre/maplibre-native) 11.11.0 отображает реальную векторную подложку [OpenFreeMap](https://openfreemap.org/). Стиль Liberty, тайлы, шрифты и спрайты скачиваются Native OfflineManager в локальный SQLite. Ключ не нужен. Источник `tile.openstreetmap.org` не используется для пакетного скачивания.

[Условия OpenFreeMap](https://openfreemap.org/tos/): небольшие области до 3000 тайлов / 50 МБ, до 4 одновременных запросов и идентифицирующий User-Agent. В приложении лимиты строже: предварительная оценка до 2000 тайлов, остановка при 2700 ресурсах / 45 МБ с учётом стиля и шрифтов. Native HTTP использует выделенный OkHttp, общий dispatcher 4/4 и `Trainster/0.2 (ru.trainster.app)`. Ограничитель фактически прочитанных байтов останавливает загрузку; метаданные Native дополнительно проверяют требуемое количество ресурсов. Незавершённый пакет не получает статус «Готово».

Загружается видимая область, уровни 0–14. Большой межгородской прямоугольник нужно разделять на небольшие участки. Пауза/продолжение/удаление доступны в приложении; Native-кеш публичных карт общий для аккаунтов на устройстве, названия приватных поездок не включаются в метаданные. Карты скачиваются каждым участником отдельно от JSON плана. Готовые пакеты сохраняются после перезапуска; обычный временный кеш не объявляется полной офлайн-картой.

SDK поддерживает также [PMTiles](https://maplibre.org/maplibre-native/android/examples/data/PMTiles/), но этот тип источника не совместим с OfflineManager-пакетами. Поэтому здесь обычный векторный tile source OpenFreeMap; импорт готового PMTiles/MBTiles не реализован.

## Пешеходные пути Valhalla

[API Valhalla](https://valhalla.github.io/valhalla/api/route/api-reference/) строит путь с `costing=pedestrian`. По умолчанию используется публичный [демосервис](https://github.com/valhalla/valhalla/blob/master/README.md) `https://valhalla1.openstreetmap.de/route`. Сервер передаёт User-Agent и X-Client-Id, ограничивает запросы до одного в секунду, кеширует до 128 маршрутов на 7 дней в SQLite. Только координаты, геометрия и метрики попадают в кеш; названия мест и участников — нет. Внешний сервис получает координаты выбранных мест, но не GPS участника, пароль или названия.

Ответ содержит polyline6: сервер проверяет и декодирует его, объединяет участки, сохраняет геометрию, расстояние, время, `routed_at` и `routing_source=valhalla_osm`. Если пути нет или сервис недоступен, возвращается ошибка, без прямой линии вместо маршрута. Новые пути требуют интернета. Сохранённые OSM-пути не удаляются по прежнему правилу MapKit. Для старых данных без `routing_source` действует прежнее 30-дневное удаление. При изменении точек путь нужно построить снова.

Для роста нагрузки замените URL в `TRAINSTER_WALK_ROUTING_URL` на собственный Valhalla. Публичный сервис без SLA предназначен для небольшого прототипа; rate limit процесса не заменяет общий limiter при нескольких workers.

## OpenStreetMap / Overpass

- [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API).
- [Overpass QL](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL).
- [Тег railway=rail](https://wiki.openstreetmap.org/wiki/Tag:railway%3Drail).
- [Лицензия и атрибуция OpenStreetMap](https://www.openstreetmap.org/copyright).

По запросу сервер получает реальные железнодорожные линии OSM вокруг выбранного участка и строит граф по общим идентификаторам узлов. Поиск пути проходит последовательно через остановки рейса. Станции сопоставляются с близлежащими рёбрами, а полученная линия следует геометрии OSM.

Результат имеет источник `derived_osm`: это предполагаемый путь по сети железных дорог, а не подтверждённая инфраструктурой РЖД нитка конкретного поезда. Возможны ошибки на параллельных путях и развилках, неполные данные OSM и несовпадение координат станций. Если пути нет, результат пустой с объяснением. Никакой подмены прямыми линиями нет.

В прототипе ограничены размер запроса, длительность, дальность и размер кеша. Используется публичный Overpass с его ограничениями; при росте нагрузки понадобится собственный/договорной источник. Координаты железнодорожных станций отправляются Overpass для построения пути. Текущая геопозиция участника туда не передаётся.

## РЖД

[Сайт продажи билетов РЖД](https://ticket.rzd.ru/) проверялся как возможный первоисточник. В этой среде получить и подтвердить официальный интерфейс геометрии не удалось. Неофициальные библиотеки и внутренние недокументированные endpoints не используются в качестве обещанной стабильной интеграции. Адаптер расписаний отделён от остального приложения и может быть заменён после подтверждения подходящего интерфейса.

## Photon: адреса и названия мест

[Photon](https://github.com/komoot/photon) предоставляет геокодирование OSM; [документация API](https://github.com/komoot/photon/blob/master/docs/api-v1.md). Демосервис разрешает умеренное использование в проектах, может ограничивать нагрузку и не даёт SLA. Прототип обращается через FastAPI к `https://photon.komoot.io/api/`; свой совместимый источник задаётся `TRAINSTER_PLACE_SEARCH_URL`.

Только явная кнопка поиска, максимум 1 запрос/секунду на процесс, до 6 результатов и кеш 7 дней / 256 поисков. Строка поиска передаётся провайдеру, но не сохраняется в обычном access log или открытом ключе кеша; пользовательский токен, имя аккаунта и GPS не передаются. Для приоритета результатов можно отправить округлённую точку предыдущего места прогулки. GeoJSON-порядок координат проверяется, некорректные результаты не заменяются фиктивными точками. На публичном сервере `lang=ru` возвращает 400; `lang=default` возвращает местные русские названия российских объектов.

Android показывает найденные название/адрес и точку для проверки. Можно уточнить положение нажатием на карту, после чего старый адрес сбрасывается, чтобы не приписывать его другой точке. Адрес в плане хранится отдельно от названия; старые конфигурации без него читаются. На карте точку выбирают без обращения к поисковому сервису; скачанная подложка работает офлайн. Источник отмечен как Photon / © OpenStreetMap contributors.


## Автобусы, внешние карты и уведомления (0.4.0)

Автобусы используют тот же документированный `search` с `transport_types=bus` и `thread` для остановок. Справочник `stations_list` хранит транспортный тип; автобусные названия дополняются населённым пунктом и регионом для различения одинаковых остановок. Старый кеш только железнодорожных станций автоматически обновляется. Сохраняются точные датированные рейсы; интервальные маршруты без точного времени не превращаются в вымышленные отправления. API не обещает полное покрытие городского транспорта. К автобусам не применяется железнодорожная трассировка OSM.

«Открыть в картах» использует стандартный [Android geo intent](https://developer.android.com/guide/components/intents-common#Maps), координаты и название точки. SDK и ключи внешних карт для этого не требуются. Назначение всегда задают координаты; выбор приложения и доступная навигация зависят от установленных карт. При отсутствии обработчика показывается сообщение.

Сервер записывает события публикации, состояния, присоединения и личных изменений в SQLite в одной транзакции с изменением. Авторизация выдаёт только события доступных поездок; личные события — организатору и указанному участнику. Тексты личных заметок не попадают в уведомление. Android хранит курсор отдельно по серверу и аккаунту, не оповещает о собственных действиях и начальной истории. Возобновление после отсутствия сети продолжает с сохранённой отметки.

В открытом приложении опрос каждые 10 секунд, в фоне — [WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work) 2.11.2 с минимальным периодом 15 минут и условием наличия сети. Android может задерживать работу. Мгновенный push-транспорт не настроен; сервер на домашнем компьютере должен оставаться доступным телефону. Фоновый worker читает события и показывает уведомления, полный план загружается при открытии приложения. Уведомление открывает поездку только для совпадающих сервера и аккаунта.

Используются отдельный канал, приватное содержимое на экране блокировки, неизменяемый PendingIntent и [разрешение POST_NOTIFICATIONS](https://developer.android.com/develop/ui/compose/notifications/notification-permission) на Android 13+. Уведомления можно выключить в приложении и Android. Отказ не блокирует просмотр и синхронизацию плана.
